# Private Gemini setup and owner-only live test

31 October 2026. **Live Gemini: NOT TESTED.** Codex used only fake providers/injected fake credentials. No real key was requested, searched for, read, created, configured or used. Tests start with a literal clean environment and a new temporary database. Do not run tests in a production process containing credentials.

## The actual secret boundary

`.gitignore`, Docker exclusions and file permissions reduce accidental exposure; they do not hide a credential from an agent or program running with the same OS permissions. Runtime code can read its injected environment. The Gemini provider necessarily receives the credential and sends authentication to Google. The hard boundary must therefore be your separately controlled production host/secret manager and its IAM, outside the Codex environment. Do not attach that host, production shell, environment, logs with secrets, or credential store to this chat. Review deployed source and dependencies before giving them runtime access. An administrator of the production OS can access runtime credentials and cached answers; no absolute isolation is claimed.

The development runners pass a literal environment allowlist, never a copy of ambient environment values. They do not load `.env` files. The production provider is lazy; health, usage, disabled and mock routes never read the key. Tests prohibit socket connections. SDK adapter tests inject fake client factories and fake credential loaders. A separate SDK subprocess enforces a wall deadline; its credential crosses only a local process boundary in memory, not CLI arguments. SDK logging is disabled there.

## Manual steps — perform outside Codex

1. Review CP10 and this repository. Use a separate browser session to access your chosen hosting dashboard and Google project yourself. Do not provide account access or the credential to Codex. No account, billing or production deployment has been configured by this work.
2. Deploy the existing Python app with `pip install -r backend/requirements.txt`. Launch with `python -m uvicorn backend.app.main:app --host 0.0.0.0 --port $PORT --workers 1 --no-proxy-headers --no-access-log`. Configure HTTPS at the host. Do not enable debug logging, request-body capture, SDK HTTP tracing or environment dumps.
3. Start with `AI_ENABLED=false` and `REASONING_PROVIDER=disabled`. Verify the no-login dashboard and deterministic examples before adding a credential. The free Render blueprint deliberately uses ephemeral storage and disables reasoning; it is not suitable for production inference budgets.
4. Mount durable writable storage on a single host; set `FINN_DB=/var/data/finn.sqlite3` or the actual persistent mount path. Back up the database privately. All workers/processes must share this exact SQLite file. Set `AI_BUDGET_STORAGE_PERSISTENT=true` only after proving the mount survives restart/redeployment. In-memory, missing and common temporary paths are rejected for Gemini; a declaration cannot prove actual host durability. Multiple hosts/replicas require a shared transactional service and are unsupported by this implementation.
5. In Google's dashboard, choose an appropriate project and create/restrict its API credential yourself. Limit API access and permissions where supported. Review current project/model quota, account eligibility, billing, data handling and region restrictions. This implementation's defaults have **not** been checked against your project quota.
6. In the hosting platform's **runtime secret manager**, create `GEMINI_API_KEY` and enter its value privately. Do not put it in the build environment, source files, `.env`, chat, commands, screenshots, logs, GitHub Actions output or checkpoint documents. Codex must not see the value.
7. Set nonsecret runtime values: `REASONING_PROVIDER=gemini`, `GEMINI_REASON_MODEL=gemini-3.5-flash-lite`, and finally `AI_ENABLED=true`. The default model was verified in [Google's model documentation](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite) on 31 October 2026; model availability/quality for your account remains untested. Provider transport uses [Google's maintained Python SDK](https://googleapis.github.io/python-genai/), pinned `google-genai==2.34.0`.
8. Start conservatively: per-client 6 attempts/minute and 20/day; global 6/minute and 100/day; 2 concurrent; daily reserved tokens 100,000; maximum input 16,000 conservative UTF-8 byte units, output 800 tokens, evidence 12,000 characters, question 2,000 characters, body 8,192 bytes; timeout 20 seconds; retries 0. Names are in `.env.example`. Lower these to fit your actual model/project quotas. If you enable `AI_MAX_RETRIES=1`, every transient retry consumes another client/global call and token reservation. Quota errors are not retried.
9. Leave `TRUSTED_PROXY_CIDRS` empty unless you have verified the precise trusted ingress CIDRs. Do not use a wildcard or broad networks. Uvicorn must keep `--no-proxy-headers`; FINN itself reads X-Forwarded-For only from trusted immediate peers, walking right-to-left. Do not allow direct client access to a supposedly trusted proxy address. Without configuration everyone behind the ingress may share one IP allowance, which is safe but restrictive. Cookies are Secure/HttpOnly/SameSite=Strict; production requires HTTPS.

## What data is sent and retained

Only the question and up to four selected public issuer snippets enter the prompt. No full PDF, research database, environment, cookie, client address or local file is sent by FINN. Tools, automatic function calls, URL context and search are disabled. Obvious emails, long account-like numbers and secret-related queries are rejected; this heuristic cannot detect every kind of personal information. Users must submit only public-company questions.

New research caches use signed browser-session namespaces, hashed keys, a one-day read expiry and a 1,000-row cap. Expired entries are pruned on cache writes, not immediately by a background eraser. Cached answers can contain the user's context even though raw questions are not stored as cache fields. Private cache responses use `private, no-store`. The old CP09 `answers` table is preserved and no longer read; an owner may review/purge it privately. Do not send database copies to Codex. Pseudonymous client identifiers are retained for current-day quota counters; source IPs are not stored by those counters. Aggregate daily usage is retained. Platform/network logs are outside these application guarantees.

Google's unpaid-service terms permit product/model improvement and human review of submitted content; sensitive information must not be submitted. Paid-service prompts/responses are excluded from product improvement, but limited safety/abuse logging remains. Retention is therefore not zero. Conditions differ by region and account; review the current [Gemini API terms](https://ai.google.dev/gemini-api/terms) before enabling a public service. Do not assume a free allowance implies confidentiality.

## Rollback and rotation

To stop inference, set `AI_ENABLED=false` and `REASONING_PROVIDER=disabled`, then restart. Keep the existing persistent DB so usage history remains intact; financial research and the dashboard continue without a model. Roll back to a reviewed release without restoring an older budget database or re-enabling inference accidentally. Rotate a compromised key yourself in Google, revoke the old key, replace the runtime secret and restart. Never paste either key into chat. If the session signer must be rotated, do so in private maintenance; existing browser sessions/caches will be invalidated. No rotation or purge was performed by Codex.
